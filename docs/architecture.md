# Agentic Engineering OS — Architecture

Framework source for a portable harness that projects agent configuration into consumer repositories. CLI: `agentic-sdlc`. Implementation language: Python 3.11+. Consumer metadata: `.agentic/manifest.yaml`. Profiles: `standard`, `secure`, `regulated` (declarative YAML, not CLI switches).

This product repo is the framework, not a consumer, until it dogfoods itself with `agentic-sdlc init`.

MVP is Milestone 1 only. Later milestones are designed here, not implied as shipped.

---

## Design principles

### 1 — LLM for judgment

Use the model for reasoning, architecture, design, implementation, diagnosis, tradeoff analysis, synthesis, and planning.

### 2 — Deterministic tools for deterministic work

Do not spend context on work compilers, formatters, linters, unit/integration tests, SAST, SCA, secret scanning, dependency checks, architecture checks, or policy engines already perform reliably.

### 3 — Guidance vs enforcement

Rules and skills guide. Hooks and CI enforce. Never treat an advisory control as a security boundary.

### 4 — Least context

Give the agent the minimum needed for the current task. Avoid large always-on instruction files. Prefer contextual rules and skills.

### 5 — Progressive disclosure

Load specialized knowledge only when it is relevant (`SKILL.md` plus referenced material, glob-scoped rules).

### 6 — Repository as executable documentation

The consumer repo holds policies, plans, ADRs, verification entry points, and agent configuration required to understand how the system is developed.

### 7 — Configuration as code

Changes to rules, skills, hooks, agents, prompts, policies, and graphs are versioned and testable.

### 8 — Security is not model obedience

Anything that must always hold needs a deterministic enforcement mechanism.

### 9 — Composability / profiles

Modular packs. Teams enable `standard`, `secure`, or `regulated` (and stack overlays) without rewriting the framework. Profiles live in `catalog/profiles/`.

### 10 — Token economics

Minimize unnecessary context, redundant instructions, repeated exploration, extra turns/tool calls, duplicate verification, and excessive output. Measure later (Milestone 5). Do not optimize before correctness.

### 11 — Harness engineering

The OS is the runtime around the model: context assembly, tool/permission policy, hooks, verification loops, retries, and stop conditions. Prompts, rules, and skills are inputs. A better prompt cannot replace a missing harness control. Cursor and Claude Code are **host harnesses**; this framework supplies a portable layer both invoke (via projected files and, later, `agentic-sdlc hook` / `verify`).

### 12 — Graph engineering

Work is a typed DAG, not a chat transcript. Nodes are steps (detect, plan, implement, verify, review, …) with artifacts as payloads. Edges are allowed transitions plus required evidence. Skills and specialized agents implement nodes. Packs, verify checks, and the SDLC chain are the same pattern at different scales. Graphs live in `catalog/graphs/`, not in `AGENTS.md`. Software walks the graph; the model fills judgment nodes.

```text
Harness: context | permissions | hooks | verify loop | stop
    -> LLM (judgment)
    -> Work graph: intent -> spec -> plan -> implement -> verify -> review -> PR
    -> Harness (trace, next node, fail/skip)
```

Milestone 1 shipped the harness skeleton and validated graph YAML. M2 adds `walk_graph` / `agentic-sdlc graph` (artifact presence and required headings).

## A. Architecture diagram

```text
                    Catalog (versioned data)
         policies  profiles  packs  stacks  templates  graphs
                              |
                    Core engine (Python)
         detect  resolve  render  ownership  manifest  doctor
         harness runtime (M3+)   graph walker (M2+)
         verify orchestrator (M3)  policy engine (M3)
                              |
                    Agent adapters (thin)
              shared     cursor     claude-code
                              |
                    Target repository
         .agentic/  AGENTS.md  .cursor/  .claude/  CI (later)
                              |
                    Deterministic enforcement (M3+)
              hooks -> format/lint/test/SAST/SCA -> CI -> PR + human
```

The engine does not speak Cursor or Claude. It resolves a **desired state** (profile + packs + stack). Adapters **project** that state into platform files. Later, hooks call the **installed CLI** (`agentic-sdlc hook …`), not ad-hoc checkout scripts.

## C. Component responsibilities and interfaces

| Component | Responsibility |
|---|---|
| CLI | Args, reports (human + `--json`). No business logic. |
| StackDetector | File/lockfile heuristics. Confidence + evidence. Never LLM. |
| ProfileResolver | Load YAML (`extends`, packs, controls). |
| PackRenderer | Compose packs + stack overlays → `DesiredState`. |
| Adapters | Map desired state → paths; reject duplicate dest. |
| OwnershipTracker | `managed` \| `generated` \| `owned`; hashes at install. |
| ManifestStore | `.agentic/manifest.yaml`. |
| Doctor | Desired vs actual: missing, stale version, hash drift, unknown stack. |
| Catalog | Schema-validated data. Rule/skill/policy/graph change = tested change. |
| Harness | `agentic-sdlc hook` policy engine + projected host/pre-commit bindings. Verify loops still M3 remainder. |
| Graph walker | Load `catalog/graphs/*.yaml`; walk artifacts on disk (`agentic-sdlc graph`). |
| PolicyEngine (M3) | Hook events → decision + explanation. |
| VerifyOrchestrator (M3) | Discover native checks; adaptive; missing = skip/DEGRADED. |

**Interfaces:**

- `StackDetector.detect(repo: Path) -> StackReport`
- `ProfileResolver.resolve(name, overlays) -> ResolvedProfile`
- `PackRenderer.render(profile, stack) -> DesiredState`
- `Adapter.project(state, repo) -> InstallReport`
- `Adapter.inspect(repo) -> ExistingAgentConfig`
- `Doctor.check(repo) -> DoctorReport`
- `PolicyEngine.decide(event) -> Decision` (M3)

## D. Configuration hierarchy

```text
organization  (optional overlay / AGENTIC_CATALOG)
  → profile     (standard | secure | regulated | custom YAML)
    → stack overlay   (language/framework)
      → repository    (.agentic/config.yaml + owned files)
        → task        (skills, contextual rules, SDLC artifacts)
```

Load order (later wins only for `owned` keys): org defaults → profile → stack overlay → `.agentic/config.yaml` → task-scoped skills/rules (not merged into always-on context).

Always-on context stays small: `AGENTS.md` / `CLAUDE.md` cover conventions, commands, architecture one-pager, constraints, definition of done, and “read `.agentic/manifest.yaml` before exploring.” Policy manuals do not belong in global instruction files.

Org-level overlay is not in M1.

## E. Cursor-specific

Projected into the consumer:

- `.cursor/rules/*.mdc` — frontmatter: `description`, `globs`, `alwaysApply`. Almost all `alwaysApply: false`. At most one short always-on pointer.
- `.cursor/hooks.json` — command hooks invoking `agentic-sdlc hook <id>` (`failClosed` for security events).
- `.cursor/skills/*/SKILL.md` — Cursor layout; default disable auto-invocation except skills that must trigger.
- Subagent briefs when emitted (narrow: verifier, security-reviewer, architecture-reviewer).

Cursor prompt hooks are out of M1 and are not security boundaries (non-deterministic).

---

## F. Claude Code-specific

- `CLAUDE.md` — short; `@` pointers allowed. Do not duplicate `AGENTS.md`; prefer “see AGENTS.md” plus Claude-only commands.
- `.claude/settings.json` — hook registrations mapped from the same policy IDs (`agentic-sdlc hook`).
- `.claude/skills/`
- `.claude/agents/` — verifier, security-reviewer, architecture-reviewer.

Hook JSON shape differs from Cursor; the adapter translates the same `Decision`.

## G. Shared layer

Independent of Cursor/Claude:

- Catalog (policies, profiles, packs, canonical text, stacks, graphs)
- Detection, resolve, render, ownership, manifest, doctor, verify
- Policy engine + explanations
- SDLC templates and `catalog/graphs/sdlc.yaml` (`intent → spec → plan → implementation → verification → review → PR`)
- CI templates and verification as a check graph
- Harness traces (later): nodes, tools, verify outcomes
- `.agentic/` in the consumer

Consumer layout (shared):

```text
.agentic/
  manifest.yaml    # generated
  config.yaml      # owned
  INDEX.md         # generated pointer map
sdlc/              # optional artifact stubs (not M1)
```

## H. Security model

Layering (guidance is not a boundary):

```text
Guidance      catalog rules/skills/AGENTS.md
Detection     doctor, secret/SAST/SCA, hook predicates
Enforcement   policy engine via hooks + CI required checks
Verification  agentic-sdlc verify + CI gates
Approval      human on PR; regulated: explicit attestations
```

**Trust:** installed `agentic-sdlc` (pinned in manifest) is trusted. Target repo files, README, web, MCP, generated code, repo-local hooks, repo-copied skills, extra catalogs are untrusted. Catalog YAML is data: schema-validate, never `eval`.

Hooks/verify are not in M1. Full threat model: [security-model.md](security-model.md). The harness (CLI + later engine) is the boundary, not the prompt.

## I. Token-efficiency strategy

Do not optimize until correctness exists (M5 measures). Design so tokens can be cut later:

- Tiny always-on files; glob-scoped rules; progressive disclosure.
- `.agentic/INDEX.md` + manifest to skip archaeology.
- Canonical catalog text once; adapters must not duplicate paragraphs across `AGENTS.md` and `CLAUDE.md`.
- Detection and doctor are CLI, not agent tool-call tours.
- One verify entry point later.
- Evals later: tokens/task, tool calls, turns, context size, retries, verify loops, success.

## J. MVP scope

**Milestone 1 (implement):** Python package + `agentic-sdlc`; Pydantic models; deterministic stack detection; existing Cursor/Claude presence detection; `init` (profile default `standard`, project minimal files, write manifest, doctor); declarative `catalog/profiles/*.yaml`; thin templates/stubs; `doctor`; tests; this documentation; `catalog/graphs/sdlc.yaml` validated not executed.

**Do not implement in M1:** hook engine; full rule/skill/agent libraries; `verify` / SAST / SCA / CI enforcement; `update` three-way merge (ownership designed now); regulated attestations; evals/token telemetry/maturity; org catalog overlay; Windows as first-class test target (`pathlib` only); LLM detection.

**Later milestones:**

1. CLI, init, manifest, detection, templates, doctor; SDLC graph data stub.
2. Cursor/Claude rules, skills, specialized agents; artifact graph walker.
3. Harness runtime: hooks, security controls, verify-as-graph.
4. Full profiles, `update`, config validation.
5. Evals on graph traces, token instrumentation, maturity scoring.

## Bootstrap, update, ownership

**Init:** detect repo → detect stack → detect existing AI config → ask only if profile unspecified or stack ambiguous (M1: default `standard` when non-interactive) → compose desired state → project → write generated manifest → doctor → report.

**Manifest (generated), example:**

```yaml
framework:
  name: agentic-engineering-os
  version: 0.1.0
profile:
  name: standard
stack:
  language: python
  package_manager: uv
  test: pytest
ownership:
  managed: [...]
  generated: [...]
  owned: [...]
files:
  - { path, class, sha256, source }
```

**Ownership:**

| Class | Update (M4) |
|---|---|
| `managed` | Overwrite only if on-disk hash matches last install. Mismatch → conflict, keep local. |
| `generated` | Always regenerate (manifest, INDEX). |
| `owned` | Never overwrite (e.g. `.agentic/config.yaml` created only if missing). |

**Conflicts:** schema validation on init/doctor; duplicate pack keys last-writer-wins with warning; two adapters writing the same path is a hard error.

**Deterministic vs LLM:** detect, resolve, render, doctor, verify discovery, hooks, SAST/SCA, ownership, schema are software. Design, implementation, review, threat-model reasoning, eval judging, plan writing are model work.
